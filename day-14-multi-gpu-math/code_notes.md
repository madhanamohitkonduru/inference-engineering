# Day 14 Step 6: code notes (vLLM v0.32.0, commit 5df63a7; read 2026-11-24)

In Qwen3, the attention input projection `qkv_proj` (`QKVParallelLinear`, a `ColumnParallelLinear`) and the MLP's `gate_up_proj` (`MergedColumnParallelLinear`) are column-parallel, and `ColumnParallelLinear` defaults to `gather_output=False`, so they do no communication (`vllm/model_executor/models/qwen3.py` lines 106-123 for attention, `qwen2.py` lines 91-104 for the MLP that Qwen3 reuses).
The attention output projection `o_proj` and the MLP's `down_proj` are `RowParallelLinear`; its `forward` (`vllm/model_executor/layers/linear.py`, lines 1762-1781) multiplies the local slice and then calls `tensor_model_parallel_all_reduce` when `reduce_results` is true (the default) and `tp_size > 1`, so there are two all-reduces per layer, as assumed.
Two more communications happen once per step, outside the layers: `VocabParallelEmbedding` all-reduces after the token lookup (`vocab_parallel_embedding.py` ~line 559), and `ParallelLMHead` shards the vocabulary so the logits are gathered across GPUs (`logits_processor.py`, `_gather_logits`); the Day 14 decode model now counts 2 x layers + 2 communications per step (it was 2 x layers; this raises the step time by about 2.8% of the communication term for Qwen3-8B).
The replicate-heads rule matches: `Qwen3Attention` computes `num_kv_heads = max(1, total_num_kv_heads // tp_size)` (`qwen3.py` line 99), asserts that TP divides the KV heads when `total >= tp` and that `tp` is a multiple of them otherwise (lines 91-98), and `QKVParallelLinear` sets `num_kv_head_replicas = tp_size / total_num_kv_heads` when `tp_size >= total_num_kv_heads` (`linear.py` lines 1053-1057), which is exactly `max(1, kv_heads / TP)` in `memory_plan.py`, so `memory_plan.py` needed no change.
Not read: how the weights are split for the output (vocabulary) shard in detail, whether the compiler fuses an all-reduce with the next normalization layer (which would change the cost of the communication but not its count), and the logits gather's message size, which is larger than the hidden-size message the model charges for it.
